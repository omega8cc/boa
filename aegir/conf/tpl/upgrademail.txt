We are pleased to inform you that your Ægir instance has been successfully upgraded to [boa.version]

@=> A more secure foundation

This release is the result of a full security audit of the entire BOA and Ægir platform. Many improvements have been made behind the scenes to protect credentials, tighten file permissions, and close potential attack paths. Your sites are now running on a hardened foundation, with no action required on your part.

@=> Important if you use CiviCRM

For security reasons, BOA no longer automatically trusts the command files that CiviCRM ships inside each site. Your CiviCRM sites continue to run completely normally under PHP -- visitors and administrators will see no difference at all. However, the behind-the-scenes Aegir maintenance tasks for a CiviCRM site (such as verify and migrate) now require a one-time control file to be enabled first. Enabling it requires root access and is not turned on by default. If you run your own BOA server with root access, create the file /data/conf/<octopus-user>_civicrm.txt for each affected account. If your server is managed by us, simply reply and let us know you use CiviCRM, and we will enable it for your account.

@=> Faster, more reliable caching

The in-memory cache layer (Valkey) has been updated and reworked for more predictable performance and cleaner recovery after a backend restart.

@=> Kernel security update -- a reboot is needed

This release includes a new Linux kernel that fixes a security issue. The reboot required to activate it is handled for you if your server is managed by us. There is no critical Drupal release in this cycle.
