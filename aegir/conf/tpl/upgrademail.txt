Hello,

We are pleased to inform you that your Ægir instance has been successfully upgraded to [boa.version]

This is the Phoenix release, named for its answer to 21 October: when PHP published a critical security release that day, the fixed versions were on your server the same day, PHP 7.4 to 8.1 among them, and PHP 5.6 to 7.3 followed the next evening, with nothing for you to do. The rest of the release follows the same idea: when something goes wrong with a site, BOA now notices, heals what it can and records the rest. Two things you may have seen already: your control panel now runs on a PHP version of its own, chosen by the server, and each of your Drupal 10 and 11 sites started once with a cold cache, as every copy of a site now has a cache of its own. Here is the tour.

----------------------------------------
PATCHED PHP, WHATEVER YOUR SITES RUN ON
----------------------------------------

Every PHP version on your server carries PHP's October security fix, from the current releases down to the versions PHP itself no longer maintains, which BOA now builds with this year's security backports. A site whose code cannot run on the PHP version it was given, an old Drupal 7 site on PHP 8 for instance, no longer answers with an error page: BOA moves it to the nearest PHP version that runs it and writes why into your account's PHP assignment file, where you can read it, and the server's administrator is told. If a script of yours keeps hitting PHP's time limit, a daily note in your account's control folder now names it, with the time, the script and the path, so a slow import or report no longer fails silently; nothing is stopped or changed. And a site whose scheduled cron keeps failing is reported to the server's administrator once a day, so a silent cron no longer goes unseen.

----------------------------------------
NEW IN THE CATALOGUE: CIVICRM, DRUPAL 12, SHOPS ON GRAV
----------------------------------------

CiviCRM is a ready platform now, for Backdrop and for Drupal 11: add a site on one of them and the panel installs CiviCRM with it and carries it through Verify, Clone, Migrate and cron. Drupal 12, still in beta, joins the catalogue for instances running PHP 8.5 or 8.6, so you can try your code on the next Drupal early. And a Grav site can now be created with a MySQL database for a KahunaCart shop, with the panel looking after the database and the shop's worker. The two CiviCRM platforms and Drupal 12 are not built through ALL: add BDC, DEC or DT0 to the platforms.info file in your account's static/control folder (ALL BDC keeps everything else as well), create an empty run-upgrade.pid beside it, and your instance upgrade starts within a few minutes; a shop needs no symbol, only a Grav site. Drupal 11 with CiviCRM, Drupal 12 and a shop all need a server on Percona 8.4, and Drupal 12 your instance's command-line and web PHP at 8.5 or 8.6; on a server still on 5.7 the build skips them and its log says why, so ask your server's administrator. The README.txt in that folder explains it, and so does https://docs.boa.io/platforms. Like every ready-made Drupal 8 and newer platform, the CiviCRM and Drupal 12 ones are for demonstration and compatibility testing; a production site belongs on a platform of your own. For a site still on Drupal 8 or 9, the mirror now carries the last cores of both, so an upgrade from such a site can be rehearsed here first.

----------------------------------------
A CACHE OF ITS OWN FOR EVERY COPY OF A SITE
----------------------------------------

Each copy of a Drupal 10 or 11 site now has its own Valkey cache namespace, so a Migrate that keeps the site's name no longer disturbs the live site while its copy runs a newer core, and sites stay consistent through a cache outage: the first request after it clears what the cache served from before. A Drupal 10 or 11 site whose cache connection fails serves the page from the database instead of an error, and Drupal 8, 9 and 10 sites keep their queues in their own database again; work a site had queued in the cache before the upgrade is not carried over, so queue it again if it matters. Two gifts for the sites still on Drupal 6: they install and run on PHP 8.1 and later again, and their database updates run again.

----------------------------------------
RENAMES, ALIASES AND SITES IN A FOLDER
----------------------------------------

A site renamed while its aliases redirected to it answers on its new name right away, a www or bare alias you added by hand moves with a rename like the automatic one, and the automatic companion is never taken when another of your sites holds it. A site's own name can no longer be its alias, and the sites in a folder of a domain keep their address through a Migrate and a Backdrop Cutover, while a folder site can no longer claim the domain it lives in.

----------------------------------------
COPIES AND RESTORES THAT FINISH FORWARD
----------------------------------------

A Restore whose last step fails after the site was replaced keeps the restored copy; a Migrate or rename whose last step fails after the old database was dropped finishes forward instead of rolling back onto an empty shell; a Clone or Migrate onto a name whose files were still there no longer links the new site to the old files; and a large site a Migrate, Clone or Restore loaded is measured before it serves, so its first visitors no longer wait on full table scans. Before a copy starts, the room check now covers the number of files it will make, not only their size, so a copy can no longer run the server out of files while the disk still shows free space.

----------------------------------------
A PANEL THAT FITS YOUR PHONE AND MOVES FASTER
----------------------------------------

The lists you open most are quicker: the sites, the tasks and the platforms. The panel fits a phone now, with columns that stack and tables that scroll in place, pop-ups that fit every window width, long domains trimmed with the full name on hover, and every row's status readable by a screen reader. The Add site form offers every language Drupal core knows, Drupal CMS included; the Migrate form compares Drupal 8 and newer and Backdrop versions correctly, so a newer platform is no longer greyed out; a site operator login sees the Platforms page and each site's platform; and the panel spells its name Ægir throughout.

----------------------------------------
FASTER, STEADIER PAGES FOR YOUR VISITORS
----------------------------------------

The shield against crawler networks now also catches the fleets that send one request per address on a browser string over a year old: in a replay of two servers' logs it turned away over ten times as many of their requests, and a visitor on such a browser still gets through by following a link or logging in; brand and media monitoring crawlers are turned away like the SEO crawlers, more AI agents are told apart, and an AI ads checker can no longer use up every site's share on the server. A site whose pages carry large cookies or a long security header no longer gets a 502 through the server's HTTPS front, a plain-HTTP visitor to one of your aliases reaches the HTTPS site in one hop, old file addresses of an imported or renamed site keep answering, and a payment gateway's notifications are no longer taken for a flood.

----------------------------------------
IN THE SHELL
----------------------------------------

The limited shell answers prompts again, so the first connection to a new host, a key passphrase or a git password are asked as they should be; tools you install with gem or npm run again; and PHP started inside a Composer run, as a Drupal CMS project or a CiviCRM platform build does, runs for every shell account, so building such a platform in your account no longer stops. vdrush, a platform's own Drush, now also works as a one-shot command from the platform root after Unlock Local Drush, so a deployment script or a coding agent can drive it; see https://docs.boa.io/using/drush/drush-basics.

----------------------------------------
BACKDROP, GRAV AND TEXTPATTERN
----------------------------------------

Backdrop gets CiviCRM as a ready platform, and a Backdrop Cutover onto a site in a folder keeps that address. On a Grav site, Reset login now signs out every remembered browser and, on current plugins, every API token, the admin's script and style files are cached by browsers for a year, and a shop's public routes stay reachable behind the admin IP lock. A Grav or Textpattern rename, Clone or Upgrade onto a name whose earlier holder left a stale alias no longer inherits its aliases and keys.
