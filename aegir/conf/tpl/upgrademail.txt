Here is what this one means for you and your sites.

----------------------------------------
RESTORE YOUR OFF-SITE BACKUPS ON YOUR OWN COMPUTER
----------------------------------------

boa-restore, a small free tool, opens the encrypted off-site backups written for your sites on your own Mac, Linux machine or Windows PC (via WSL), with no server involved at all. It lists what is there, restores a single file or a whole site to a chosen moment, never overwrites anything, and physically cannot write to the backup storage. The guide walks you through a fire drill that turns "we have backups" into "we have tested restores": https://docs.boa.io/using/backups/disaster-proof-restore

One related note: if your off-site backups go to Google Cloud Storage or IBM Cloud Object Storage, both destinations work again and now use a different kind of access key. Rewrite the credentials file in your account with the variable names its README lists, or ask your server administrator; until then, a run to that destination stops with a clear message instead of failing silently.

----------------------------------------
MIGRATIONS BECOME A TASK, NOT A PROJECT
----------------------------------------

A new Migration source task appears on your Drupal 8+ sites: pick another of your own sites, and its database is instantly readable by Drupal's migration tools as the standard 'migrate' connection -- no credentials to collect, no connection strings to assemble. The access is read-only, covers exactly that one database, and lasts until you set it back to None; deleting either site removes it, and a clone never inherits it.

----------------------------------------
A QUEUE THAT HEALS ITSELF
----------------------------------------

A task whose runner was killed mid-flight -- a restart, an interrupted upgrade -- used to sit at Processing forever and block everything queued behind it. Such tasks are now detected and marked Failed with an honest log entry within minutes, your running counts stay true, and nothing is ever re-run behind your back: a failed migrate or clone is yours to re-fire when you choose. Tasks still running when your instance is upgraded are finished first instead of being cut off by the upgrade itself.

----------------------------------------
YOUR BACKUPS KNOW WHAT THEY ARE
----------------------------------------

Every backup is now recorded with the kind of archive it really is -- complete, database-only or files-only -- including the automatic safety copy taken before every Restore, ready for your Backups list to show and sort on. And the safety copy can no longer be quietly downgraded by another backup task running at the same moment: what the task asked for is what gets saved.

----------------------------------------
CERTIFICATES BEHAVE, EVEN UNDER PRESSURE
----------------------------------------

When several certificate tasks run at once, a Verify that could not get its certificate now says so and asks for one more Verify, instead of reporting success and leaving the site's HTTPS broken. A certificate is wired in only when every file it needs is really there, and a custom certificate you installed yourself now survives the nightly renewal untouched.

----------------------------------------
A DELETED SITE LEAVES NO GHOST BEHIND
----------------------------------------

Deleting a site and creating a new one under the same name used to occasionally serve leftovers of the old site from the shared cache. The old site's cache namespace is now purged at Delete and again before the new site installs, on Drupal and Backdrop alike, so a recreated site always starts clean.

----------------------------------------
FRESHER FOUNDATIONS FOR YOUR NEXT PROJECT
----------------------------------------

Four distributions return to the platform catalogue rebuilt on current cores: Varbase 10.1.2, OpenFed 13.6.6, Opigno LMS 3.2.7 and Open Social 13.0.2. The Drupal CMS platform now carries everything needed to act as a Drupal 7 upgrade target out of the box. And sites still running on the oldest supported PHP keep their database connection everywhere, including on servers running the newest database version -- nothing to change on your side. If you pin which platforms get built in your account's platforms.info file, note that these four distributions moved to new core groups, so check the symbols there still say what you mean.

Two housekeeping notes. If you turn Solr search off for a site by clearing its search setting in the site's control file, that now really does remove the site's search index rather than leaving it in place -- the index is archived on the server first, and a control file the system itself rewrites never triggers a removal. And nightly cleanups now defer while one of your tasks is running, logging that they deferred; the work simply runs on the next pass.

Curious about the details? The full story of this release is at https://docs.boa.io/releases/boa-5-88-855
